# 使用说明

## 一、选择模式

| 模式 | 请求方式 | 典型产物 |
|---|---|---|
| 完整初稿 | 从数据、图件、笔记或中文草稿写整篇论文 | 完整稿件 + 假设 + 缺失输入清单 |
| 章节起草 | 摘要、引言、结果、讨论、方法、综述或 Perspective 章节 | 可直接粘贴的章节 |
| 结构重建 | 重组旧稿 | 新架构 + 重写章节 |
| 润色 | 句段修订 | 修订文本 + 修改记录 |
| 格式调整 | 转换为目标期刊格式 | 合规版式、参考文献、声明、图注 |
| 图件套件 | 为断言制作投稿图件 | 图件合同、文件、图注、审核 |
| 审稿回复 | 审稿意见 + 修改事实 | 回复信 + 跟踪表 + 修改清单 |
| 编辑审核 | 稿件 + 目标期刊 | 契合度评估、就绪状态、缺失事实清单 |
| 投稿包 | 稿件 + 作者事实 | cover letter、标题页、声明、审稿人建议 |
| 统计审计 | 方法/结果/图注 | P0/P1/P2 问题、修订文字、AUTHOR_INPUT_NEEDED 清单 |
| AI 诚信审计 | AI 辅助稿件 + 目标期刊 | 披露声明、禁止用途检查、引文/数字核实 |
| 文献审计 | 稿件/综述 + 断言 | 检索记录、证据表、已核实引文 |
| 校对 | 全文或章节 | 五轮问题日志 + 修订文本 |
| Perspective 开发 | 主题/笔记/范例 | 智识中心、发现序列、草稿 |
| Perspective 生产 | 设计文档/作者文本 | 六节稿件、Box/图、双语包、模板 |
| 作者忠实编辑 | 源文件 + 模式 | 修订副本、修改记录、待确认问题 |
| 理论文章审读 | 稿件 + 断言 | 证据台账、三学科审读、图件/格式审查 |
| 投稿前评审 | 稿件 | 三份审稿报告 + 综合意见 |

## 二、需要提供什么

- 核心论断（一句话即可）；
- 证据：图、表、分析、统计、数据；
- 边界：断言止于何处；
- 目标期刊或文章类型；
- 不可更改的术语；
- 语言：英文、中文或中英对照。

缺少论断、证据或边界时，技能返回带可见占位符的骨架，不编造内容。

## 三、完整论文流程

1. agent 复述一句话论证、论文类型、提纲和术语表；
2. 把每条断言映射到证据并标出缺口；
3. 先写结果，再写引言/结论、讨论、方法、摘要、标题；
4. 做一致性检查（数字、单位、图表引用、引文顺序、时态、断言强度）；
5. 执行对抗性自审；
6. 交付稿件包：标题页、摘要、正文、方法、参考文献、图注、扩展数据清单、声明、假设、修改记录。

## 四、图件流程

1. 写图件合同：核心结论、原型、面板地图、证据层级、统计、源数据、审稿风险；
2. 选择 Python 或 R，后端独占绘图、预览与导出；
3. 按阅读顺序选面板：体系/设计 → 主要比较 → 机制/定位 → 量化 → 稳健性；
4. 应用期刊规格与项目门槛（字号、栏宽、颜色角色、间距、面板字母、图注统计）；
5. 导出 SVG/PDF 与 300–600 dpi 位图；SEAL 任务把每个 panel 导出为独立可编辑 SVG，并记录审核；
6. 交付图件、图注、源数据映射与发布检查。

起步脚本：

~~~bash
python skills/natsci-writing-zh/assets/code/figure_python.py --demo --out ./figures
Rscript skills/natsci-writing-zh/assets/code/figure_r.R --demo --out ./figures
~~~

## 五、编辑审核与投稿

1. 确认阶段（首次、返修、原则接收、校样）并核对期刊/文章类型限制。
2. 用各一句话评估原创性、重要性、跨学科兴趣、可靠性与可读性。
3. 执行"为什么是这个/现在/广泛"测试，写出领域外受众。
4. 建立交付矩阵；只根据作者确认事实起草 cover letter、标题页、声明与审稿人建议。
5. 返回 ready / ready_with_author_checks / blocked，列出缺失事实。

## 六、创新与定位

分类贡献类型与阶梯；写明确切科学未知；列出竞争解释与区分性预测；测试广泛兴趣；公平定位最接近前人工作。使用创新画布模板。

## 七、统计审计

定义独立单位与重复层级；检查精确 n、误差定义、检验、尾向、校正与精确 P；对齐图注与 Source Data；检查 Reporting Summary、图像诚信和数据/代码/材料声明。返回 P0/P1/P2 问题与 AUTHOR_INPUT_NEEDED 清单。

## 八、修订流程

先修推理：章节任务、claim → evidence → boundary、沙漏结构、主题句；再处理语法与语域。除非确认结构性调整，只改被指出的段落。返回修订痕迹、中英对照（如有要求）和修改记录。

## 九、审稿回复流程

逐字保留审稿意见；分类；映射到动作与稿件位置；缺失事实标 AUTHOR_INPUT_NEEDED；语气合作、证据优先、不防御。交付策略摘要、跟踪表、回复信、修改清单和风险提示。

## 十、双语交付

- 英文论文配中文笔记时，按需交付英文正文和对应中文版本；
- 相对作者最新文本，新增和替换文字加粗；
- 两种语言的证据强度一致：候选、相关、预测、已证明（限测试范围）；
- 独立中文论文使用 natsci-writing-zh，直接写原生中文，不写英文脚手架的中译。

## 十一、提示词模式

- "这是我的论断、图件和笔记。写完整的 Nature Article，缺失内容标出来。"
- "只写讨论，保留我的结果和术语。"
- "把这篇稿件转成 Nature 格式，不改变科学含义。"
- "做整套图件，先问我 Python 还是 R，先给合同和面板地图。"
- "起草回复信，这是审稿意见和我的修改记录。"

## 十二、Perspective 与作者保真门

- Perspective：一个论点、六节、五级证据台账、整段正文、论证内无列表、边界集中一段、每小节 2–3 句单句加粗洞见、概念图与图注在末尾。
- 编辑：约定轻度润色/作者忠实扩写/结构重写/翻译/修订模式；保护作者断言顺序和措辞；复制源文件；保留修改记录。
- 双语：断言、数字、引文、确定性和强调一致；中文自然，英文对应学术。

## 十三、AI、文献与校对门

- AI 诚信：查目标期刊政策；记录工具/任务；移除机密材料；核实 AI 建议的每条文献/数字；写披露；确认人类能辩护每一句。
- 文献：记录数据库、检索式与日期；筛选与提取；按问题/机制综合；核实每条 DOI/题名/作者及预印本/撤稿状态；保留文献库。
- 校对：五轮扫描，再核数字、单位、统计、参考文献、图表引用和标记；列出待作者核实问题。

## 十四、常见错误

- 论断和证据未定就要求写正文；
- 只给图不给源数据或统计，图注无法诚实完成；
- 在同一交付物中混用期刊印刷字号与 HTML/项目大字号；
- 只需局部修补却要求全文重写；
- 期望技能编造实验、引文、行号或审稿人。
