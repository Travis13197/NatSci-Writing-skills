# 完整论文生产：初稿、修订与格式

版本 1.0.0；更新日期 2026-11-23。用于从材料生成完整论文或章节、重建论文架构、转换或排版稿件、准备投稿包。本文件把 nature-skills 写作体系与 SKILL.md 中语料校准的标准整合为可执行流程。

## 一、交付模式与路由

| 模式 | 输入 | 输出 |
|---|---|---|
| 完整初稿 | 想法、数据、图件、笔记、中文草稿 | 按目标期刊结构组织的完整稿件，附假设与缺失输入清单 |
| 章节起草 | 章节要求与论断/证据 | 可直接粘贴的完整章节 |
| 结构重建 | 结构有问题的旧稿 | 新架构与重写章节，保留修改痕迹 |
| 润色修订 | 接近完成的文本 | 句段级修订与修改记录 |
| 格式转换 | 稿件与目标期刊 | 符合期刊要求的版式、参考文献、声明、图注 |
| 图件套件 | 数据与论断 | 投稿级图件、图注、源数据映射 |
| 审稿回复 | 审稿意见与修改事实 | 逐点回复、跟踪表、修改清单 |
| 投稿前评审 | 稿件 | 三份审稿报告与综合意见 |

只在答案会改变交付物时追问核心要素：核心论断、证据、边界、目标期刊、章节范围。关键输入缺失时生成带显式占位符的骨架，不虚构内容。

## 二、接收与确认门

起草完整章节前，提取并复述：
- **一句话论证**：在[体系/问题]中，我们用[方法]展示[推进]，由[证据]支持，边界为[范围]。
- **论文类型**：research / methods / algorithmic / hypothesis / review。
- **计划**：目标期刊、字数、章节、段落地图（每段一个任务）。
- **术语表**：方法、模型、数据集、指标、缩写的规范形式；标出冲突。
- **读者首要问题**：相关性、新颖性、可信度、可复用性、意义——摘要和引言应依次回答。
- **假设与最多 2–3 个高杠杆问题**。

论断、证据或框架有歧义时停下确认；作者已给出完整信息时，用一行说明论证后直接写作。长稿件先给提纲再展开全文；对提纲的反应成本远低于对全文的反应成本。

## 三、术语表

同一个事物全文只有一个名称：标题、摘要、正文、图、表、补充材料、回复信一致。记录规范术语、首次展开、原文变体与决定。不为作者的方法生造名称；缺失或不一致时询问或标记。后续章节沿用同一术语表；术语一旦更改，全文同步替换。

## 四、完整论文流水线

1. **任务与范围**：目标期刊、文章类型、读者、篇幅、截止时间、现有材料。
2. **论证**：一句话论证；贡献类型（机制、能力、测量、资源、理论）；最接近的前人工作。
3. **证据映射**：每条断言 → 图/表/分析 → 强度 → 边界；无支撑断言标为缺口。
4. **架构**：选择论文类型 playbook 与章节字数预算；写段落地图（每段一个任务）。
5. **摘要与标题草稿**：作为方向标早写，最后定稿。
6. **按证据顺序起草**：先结果，再引言/结论，再讨论、方法、摘要、标题。避免引言承诺结果没有兑现。
7. **章节打磨**：应用第五节 playbook。
8. **一致性检查**：术语、数字、单位、图表引用、引文编号、时态、断言强度。
9. **对抗性自审**：按第十一节检查拒稿风险，修正断言、证据呈现或范围。
10. **打包**：稿件、图件、图注、声明、参考文献、补充材料；如需要附 cover letter。

研究论文起草顺序：结果 → 引言与结论 → 标题 → 讨论 → 方法 → 摘要。方法学/算法论文：方法 → 结果/基准 → 引言 → 讨论 → 摘要。

## 五、章节 playbook

### 标题
具体且可检索：对象/系统 + 能力/动作 + 应用/后果；常见 8–12 词；Nature 标题多为紧凑名词短语。避免"Towards…""A study of…"、未核实的"首次"、口号和未解释术语。给 3–5 个候选（陈述式、发现式、极少用问句），标出最可辩护者；核对候选中的定量表述。

### 摘要
Nature 研究论文：约 200 词、7–8 句，分阶段：广域领域 → 更具体背景 → 确切问题 → "Here we show"主结果 → 结果改变了什么（2–3 句）→ 有边界的更大背景。Science：约 125 词、5–6 句，以后果收尾。不要在背景不足时以"Here we show"开头，不要以空泛承诺结尾。

Nature summary paragraph 的内部逻辑（起草或重建 Nature 摘要时使用）：
1. 1–2 句跨学科读者能懂的领域背景。
2. 2–3 句具体背景与理解问题所需的最少概念。
3. 一句毫不含糊的缺口句。
4. 一句主结果，用"Here we show"或等价句式。
5. 2–3 句解释结果改变了什么，不罗列更多结果。
6. 1–2 句更大的背景，锚定在证据上。
7. 可选的 2–3 句更广视角；只有期刊允许时才扩展到约 250–300 词。

其他期刊的默认摘要动作：背景/问题 → 现有路径为何不足 → 本文提出什么 → 最强结果（含数字/比较）→ 机制或后果 → 有边界的意义。摘要是迷你论文，最后写、改得最多。

### 引言
受控漏斗：领域重要性 → 现有实践瓶颈 → 前人工作解决了什么、没解决什么 → 剩余能力缺口 → 本文作为直接回应。通常四段。明确写出"已知"到"本文"的过渡。引用用于定位，不用于展示阅读量。不提前详述结果与数字；末段预告贡献与方法。

可选变体（说明使用哪一个）：先任务后应用；应用先行；一般到具体；以挑战开篇；新任务—挑战分解；技术瓶颈；流程/模块框架。

### 结果/实验
证据阶梯：体系/流程验证 → 主要结果 → 公平基线比较 → 机制/消融 → 应用/泛化 → 压力测试/失败模式。每小节先问题，再设计，再带定量支持的观察，最后推论。观察用过去时；除非有意过渡到讨论，解释保持简短。每个主要断言需要比较、消融或压力测试证据；没有就标记待补，不绕写。不把应放正文的结果藏进补充材料；不重复图中的每个视觉细节。

### 讨论
解释而非复述：核心推进 → 证据含义 → 竞争解释 → 与最接近研究的关系（支持/修正/复杂化）→ 具体局限与断言止点 → 现在可检验或可使用什么。在解释需要处使用限定语；不把"与……一致"升级为"证明"。局限必须写出实际条件/数据集，不写泛泛谦虚。以具体机会或开放测量收尾，不赞美本文。

### 结论
四部分收尾：核心贡献 → 决定性证据 → 意义 → 边界。不引入新数据、新引文或新机制。意义范围不得大于证据范围。

### 方法
可复现性测试：另一课题组能否据本描述加引用方案重复？结构：设计/队列 → 材料或数据来源 → 流程 → 结局指标 → 分析与统计 → 伦理。写清实际核实的输入、变换、检验定义、对照、软件/资源版本与参数；未知设置不填常见默认值。不写"在标准条件下""采用常规方法""进行了统计分析""样本被随机分配"等空话。

### 相关工作（期刊要求时）
按方法或假设分组，不逐篇罗列；说明每条路线做到了什么、对当前问题哪里不够；落在本文要填补的缺口。不用相关工作推迟交代贡献。

## 六、论文类型 playbook

| 类型 | 论证链 | 起草顺序 | 关键证据要求 |
|---|---|---|---|
| Research | 领域需求 → 瓶颈 → 推进 → 决定性证据 → 意义 → 边界 | 结果先行 | 每条断言有比较/消融/压力测试 |
| Methods | 任务 → 现有方法局限 → 新方法 → 公平评价 → 可复现 → 边界 | 方法先行 | 基线、协议、失败模式 |
| Algorithmic | 问题 → 局限 → 模型/系统 → 公平比较 → 消融 → 泛化 → 边界 | 方法/架构先行 | 数据划分、随机种子、指标定义 |
| Hypothesis | 观察 → 竞争解释 → 区分性预测 → 定向检验 → 机制判定 | 检验/结果先行 | 能区分解释的实验 |
| Review | 领域现状 → 框架 → 按机制综合 → 分歧/证据质量 → 开放问题 | 框架先行 | 综合而非逐篇摘要 |

## 七、期刊格式（投稿前核对当期指南）

| 期刊 | 摘要 | 正文 | 展示项 | 参考文献 |
|---|---|---|---|---|
| Nature Article | 不超过 200 词，分阶段 summary paragraph | 约 2,500 词（6 页）或 4,300 词（8 页）；小标题不超过 40 字符 | 4–6 幅主图 | 不超过 50 条 |
| Nature Review | 不超过 200 词前言，以总结句收尾 | 少于 7,000 词；聚焦一个专题 | 4 个展示项；鼓励 Box | 不超过 150 条 |
| Nature Perspective | 格式同 Review；个人视角、前瞻、范围窄 | 论证式短文 | 1–4 个 | 选择性 |
| Science Research | 约 125 词、5–6 句 | 结果驱动 | 4–6 幅主图 | 期刊格式 |
| Science Review | 约 120 词 | 有框架的综合 | 3–4 幅图 | 期刊格式 |
| Science Perspective | 一句提要约 11 词 | 短论证文 | 0–2 个 | 选择性 |
| Nature Communications | 约 150 词，面向广泛读者 | 灵活 | 4–8 个 | 期刊格式 |

要求合规时使用目标期刊的当期指南，不凭记忆套用旧限制。

## 八、完整稿件包

完整初稿应交付：
1. **标题页**：标题、作者与单位（未知用占位符）、通讯作者、关键词（如需）。
2. **摘要**：按期刊结构；中英双语流程附中文版。
3. **正文**：带章节标题和段落级论证。
4. **方法**：可复现细节与统计。
5. **参考文献**：已核实并按目标格式排版；正文编号置于标点前（作者偏好），期刊规则优先时从其规定。
6. **图注**：与实际面板一致；图件另附文件。
7. **扩展数据/补充材料**：清单与图注。
8. **声明**：数据可用性、代码可用性、作者贡献、利益冲突、致谢、伦理/知情同意。
9. **假设与缺失输入清单**：作者必须补充的内容，明确标出。
10. **修改记录**：位置、原文、新文、理由。

输出格式：审阅用 Markdown，合作者用 DOCX，期刊要求时用 LaTeX，交互审阅用 HTML。数字保留单一事实来源；表格从源数据生成，不重复手抄。

## 九、格式转换

- 保留内容与科学含义；只改版式，不改断言。
- 应用目标期刊结构：标题页字段、摘要标题、章节顺序、图表位置、参考文献风格、行号、页面与字体。
- Nature 风格参考文献：编号制，作者姓+首字母，包含文章标题；Science 按当期指南。同一稿件不混用风格。
- 公式：显示公式用 MathML 或真实 TeX 渲染；Unicode 伪下标不是公式。核对分式、上下标、范数与希腊字母的渲染结果。
- HTML 中把关键比较、效应、计数或区间置于 strong 强调中，同时保留完整句子和分母；表格放在局部滚动容器；检查桌面与移动端宽度。
- 图件：线条图用矢量，照片 300–600 dpi 位图，RGB，嵌入字体，文件名与图号一致。
- 格式转换中不静默"修正"数字、作者名单、单位或基金；发现差异写入修改记录。

## 十、声明与元数据

数据可用性：写清仓库、登录号/DOI、内容、版本/日期；受控数据写限制原因、申请途径、资格与审核、可公开的元数据。不得只用"可向通讯作者索取"而无原因、持久途径、资格与元数据。区分自产、复用、授权和受控数据。代码可用性：仓库、发布版本、许可证、环境与入口。作者贡献：按期刊类别（如 CRediT）核实。利益冲突：写实际财务/非财务利益，或"作者声明无利益冲突"。伦理：批准机构、批号、知情同意流程。声明必须具体、持久、可核验。

引文管理：加入前核对题名、作者、年份、期刊、DOI、发表状态；从已核实元数据导出 RIS/BibTeX/Zotero RDF；一条记录一篇文献；去重；不编造字段。文献库与稿件放在一起。

## 十一、投稿前对抗性自审

用稿件中的明确证据回答，标记"通过/需修改/需补数据"：
- **贡献**：新增什么知识？失败案例是否有意义？想法是否非显然？增益是否意外而非可预测？属于哪种新颖性？
- **写作清晰度**：懂行的读者能否复现方法？每个模块动机是否明确？术语与符号是否一致？每段是否只承载一个信息？
- **实证强度**：相对强基线的增益是否有意义、跨数据集/设置是否一致、失败案例是否如实呈现？
- **评价完整性**：关键设计是否都有消融？近期强基线是否在公平设置下比较？指标是否标准且充分？数据集是否足够有挑战？协议是否记录？
- **方法可靠性**：实验设置是否现实？是否有隐藏缺陷？是否无需逐例调参就稳健？收益是否大于复杂度和新局限？
- **期刊契合度**：广泛读者是否关心？影响是否直接？非专家能否读懂？

反复修正断言、证据呈现或范围，直到没有主要拒稿风险。
