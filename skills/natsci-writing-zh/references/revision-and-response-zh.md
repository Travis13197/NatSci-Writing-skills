# 修订、润色与审稿回复

版本 1.0.0；更新日期 2026-11-23。用于句段级润色、按期刊格式修订、审稿回复包或投稿前审稿模拟。

## 一、润色先修推理

一段读起来漂亮但承担错误修辞任务的文字是失败的修改。先做：
1. 明确章节任务与段落单一任务。
2. 检查每个重要段落的 claim → evidence → boundary；先补缺失证据或缺失边界，再改词。
3. 检查沙漏结构：引言由宽到窄，讨论由窄到宽。
4. 检查段落顺序与主题句；反提纲失败就先修架构。
5. 最后处理语法、用词、节奏和语域。

## 二、修订机制

- 只改用户指出的段落或断言，其余逐字保留；无声全文重写会破坏本来正确的段落，并迫使作者全部重查。
- 若修复必须结构性调整，先说明新结构并确认，再执行。
- 术语表保持稳定；不重新引入已废弃变体。
- 只重跑与改动相关的检查。
- 用户转向揭示原前提错误时，回到论证/确认环节，不在错误前提上继续修文。
- 记录修改：位置、原文、新文、理由。中英对照交付时两种语言都加粗新增/替换文字。

## 三、章节动作（修辞功能）

把这些当功能而非模板；句子必须包含具体科学内容。

**引言**：重要性 → 已知 → 缺口/争议 → 目的 → 价值/方法。避免编年史、详述结果、在缺口前宣称新颖。

**方法**：设计/队列 → 材料/数据 → 流程 → 结局 → 分析/统计 → 伦理。可复现是标准。

**结果**：指向图/实验 → 主要观察 → 定量细节 → 预期/非预期模式 → 仅在有助于解释时比较。避免在此写长篇机制解释。

**讨论**：主要发现 → 合理解释 → 与早期研究关系 → 局限 → 意义 → 后续问题。不复述结果；不从相关推机制。

**结论**：目的 → 决定性发现 → 贡献/意义 → 边界/展望。不引入新实验。

**摘要**：背景 → 缺口 → 方法 → 关键结果 → 意义。选择性；不影响编辑初筛的细节通常不属于摘要。

**标题**：核心对象 + 机制/语境，或过程 + 结果 + 系统；可检索、具体、克制、可辩护。

## 四、按证据强度选词

- 强：表明、显示、证明（限范围）、揭示、识别——只在设计与数据支持时使用。
- 中：提示、说明、支持……观点、与……一致、指向。
- 推测：可能反映、或源于、似乎、或许可以用……解释。

缺口表达：仍不清楚、尚未在……中检验、关注有限、少有研究处理、证据仍稀疏。避免"从未有人研究""完全未知"。

比较：与……一致、与……相符、大体支持；分歧：与早期报道相反、与……不同、造成差异的一个可能原因是……。

局限：把局限与真实不确定性来源配对（"单中心队列限制了外推"），不写泛泛谦虚。

意义与展望必须落在证据边界内；未来工作要来自真实局限、不确定性或机会。

## 五、风格红线

- 不使用缩写口语、反问和聊天式填充；第一人称只在学科与期刊接受时使用。
- 缩写首次出现定义；同一术语一种拼写；Nature 风格默认英式拼写，除非期刊另行规定。
- 测量用数字；数值与单位间留空格；范围用连接号；统计符号统一。
- 一句一个命题；从句依附主句；不用逗号连接两个独立句；每段有控制性观点。
- 标记并弱化 prove、conclusively、unprecedented、best、superior、first；改用 to our knowledge、among the strongest、in this cohort。
- 图注简洁（Nature 风格不超过 300 词）；标题不超过 75 字符（含空格），除非期刊另有规定。
- 不把相关升级为因果，不把结论推广到研究范围之外。

## 六、审稿回复包

默认包：回复策略摘要 → 意见—回复跟踪表 → 逐点回复信 → 稿件修改清单 → 缺失信息/风险提示 → 中文核对说明（作者用中文时）。

决定类型：小修、大修、修回复审、审后转投、类申诉（单独路由）、不明确。

流程：
1. 先提取编辑指令（E.1、E.2），再处理审稿意见（R1.1、R2.1）。
2. 逐字保留审稿意见，不转写成更容易回答的版本。
3. 分类：文字、分析、实验、图件、澄清、引文、弱化断言、部分接受、不同意、超出范围、需要作者输入、阻塞。
4. 每条映射到具体动作与稿件位置；位置或事实未知时标 AUTHOR_INPUT_NEEDED。
5. 回复写直接答案、已采取动作、位置和剩余局限；不能只写"感谢意见"或"已相应修改"。
6. QA：每条都有回应；不编造实验、引文、行号或面板；断言与新证据一致；语气合作、证据优先、不防御。

动作标签：ACCEPT_TEXT、ACCEPT_ANALYSIS、ACCEPT_EXPERIMENT、ACCEPT_FIGURE、CLARIFY_EXISTING、ADD_CITATION、SOFTEN_CLAIM、PARTIAL、DISAGREE、OUT_OF_SCOPE、AUTHOR_INPUT_NEEDED、BLOCKING。

语气：
- 合作但不卑微；证据优先而非人格化；简洁到编辑可快速核查。
- 不同意顺序：承认关切 → 窄范围指出分歧 → 给证据或范围逻辑 → 若原文可能引起混淆，做小幅澄清。
- 把"审稿人误解"当作表达信号（"原文没有把这个区分说清楚"），不写"审稿人误解"。
- 超出范围的请求：先承认价值，再说明设计/范围原因，弱化断言并补局限；不以时间、经费或便利为首要理由。

## 七、投稿前审稿模拟

除非另有要求，返回三份审稿报告加综合意见。评审轴：原创性；科学重要性；跨学科读者兴趣；技术可靠性/技术缺陷；非专家可读性。审稿人 1 侧重技术可靠性，2 侧重原创性与重要性，3 侧重广泛兴趣与可读性；三人都简要覆盖全部轴。

每份报告：总体评价；谁会关心及为什么；主要优点；主要关切；建立作者主张前必须解决的技术缺陷；按五轴评估；推荐姿态。综合意见：共识优点、共识技术风险、侧重点差异、广泛兴趣判断、建立强主张前最重要的问题。标出无支撑或无法从材料评估的断言；不编造审稿人身份或稿件细节。

## 八、期刊格式修订检查

- 结构与标题顺序符合目标期刊；摘要不超限；需要时有关键词。
- 参考文献：风格统一、编号/引用顺序正确、DOI 已核实、无重复、无撤稿文献。
- 图件：图号与面板字母与图注和正文一致；源数据与许可有记录；文件格式和尺寸符合要求。
- 声明：数据/代码可用性、贡献、利益冲突、伦理；每条具体且持久。
- 公式和符号渲染正确；表格可编辑；补充材料按顺序列出并在正文引用。
- 按要求提供修订痕迹或清稿；文件名与版本清楚；保留原始文件。

## 九、审稿侧审计与回复包一致性

以审稿人或准备回复时，用技术关切分类而非泛泛褒贬：

- **设计**：抽样、对照、随机化、盲法、功效、混杂、泄漏。
- **证据**：无支撑断言、缺少比较、效应量弱、过度外推、因果越界。
- **统计**：独立单位、伪重复、多重性、模型假设、精确报告。
- **可复现**：缺参数、软件/版本、数据/代码获取、方案细节。
- **图件**：证据密度、面板逻辑、统计呈现、图像诚信、图注一致。
- **断言与新颖性**：首创、与前任距离、渐进框定、标题/摘要与证据不匹配。
- **伦理与合规**：知情同意、批件、两用、利益冲突、AI 披露、许可。

严重度：P0 可能动摇核心断言；P1 削弱可评审性或可信度；P2 为清晰度/一致性问题。审稿人 1 侧重技术可靠性，2 侧重原创性与重要性，3 侧重广泛兴趣与可读性；三人都简要覆盖全部轴。

**取证式一致性审计**：定稿评审或回复前，交叉比对稿件、图、图注、补充材料、cover letter 与回复信中的数字、样本量、排除、随机化、软件版本、图/面板数、登录号、参考文献与声明；标出矛盾，不静默调和。回复信不得声称稿件没有的修改；每条声称的修改都要有位置或明确的 AUTHOR_INPUT_NEEDED 占位。

**回复包一致性**：策略摘要 → 跟踪表 → 回复信 → 修改清单 → 风险提示。逐字保留审稿意见；每条给动作与稿件位置；保持就绪状态（ready / 带占位草稿 / 需作者输入 / blocked）。没有决定信时不要编造编辑指令；决定类型不清时询问或标记。

**审稿人可见性与角色边界**：审稿报告中不写成作者；不宣称编辑决定；不编造审稿人身份或行号。AI 可辅助语言，但审稿人不得把稿件上传公共 LLM，也不得以模型输出替代独立判断；期刊要求时披露 AI 辅助。
