# SEAL 补充图制作规范

版本：1.1.0；更新日期：2026-11-18。创建、重绘或审核任何 SEAL 主图或补充图前，必须完整阅读本文件。

## 一、适用范围

本规范适用于全部 28 张 SEAL 补充图，以及后续重新生成的所有补充图面板；同时记录主图 Figure 1–4 的已确认约定。作者后续明确要求优先于通用图件默认值。

## 二、所有补充图必须遵守的文字与坐标轴规则

- 普通文字为 8 pt；任何关键注释都不得仍停留在 4–6 pt。
- x/y 轴标题和面板标题为 10 pt。
- 面板字母为 10 pt 粗体，不得覆盖数据、刻度、图例或图注。
- 图例和直接标签通常为 8 pt；关键数值不依赖悬停即可读取。
- 坐标轴和主刻度线宽为 0.4 pt；端点和连接使用 rounded cap/join。
- 主网格线不得粗于 0.35 pt，并应弱于数据。
- 常规分析面板的数据框必须接近正方形，`plot_box_width / plot_box_height = 0.9–1.1`，使用 `set_box_aspect(1)`。
- 拥挤时通过调整画布、网格、换行、直接标签位置或刻度密度解决，不得缩小字号保留全部标签。
- 注释文字放在点云外部、页边或有序标签栏中，不得用类别名或簇名覆盖数据点。
- 所有 SVG 必须保留可编辑文字，不得把文字转成轮廓。

上述规则适用于所有补充图，而不仅是被当前修改的图。

## 三、颜色与数据点显眼程度

- 图例必须使用实际绘制的颜色，不得出现图例颜色明显浅于数据点的情况。
- 主要注释观测使用全饱和标记；除非为解决严重重叠，否则关键类别使用 `alpha = 1`。未注释背景使用登记过的中性浅灰。
- 早期项目基础色保留为参考：红色 `#9B4B4B`、浅蓝灰 `#6C839C`、蓝色 `#3E7A9E`、深蓝 `#4A5E87`、绿色 `#5A9199`、灰色 `#939393`。
- 当前主图使用实测终版色盘：slate `#536F89`、coral `#B96359`、teal `#438E7B`、purple `#8179A8`、ochre `#A97936`、补充蓝绿和中性灰。若作者明确要求补充图与主图一致，实测终版色盘优先于历史基础色；发生替换时记录映射。
- 同一生物学类别在主图、子图、结构重叠图、图例、图注和 HTML 中必须保持同一颜色；不得静默改色。
- 数据点必须按最终发表尺寸可见。600-dpi SEAL 补充图中，基准图种子点使用 `s >= 12`；家族子图点 `s >= 8`；结构汇总点 `s >= 16`；20,420 蛋白彩色覆盖点 `s >= 10`。
- 若评审认为家族子图点过小，应把点面积相对上一稿约放大 4 倍，或调整布局达到同等可见性；不得因为原代码已有点径就保留显微镜级小点。
- 除颜色外必须同时使用点形和直接标签提供冗余识别。

## 四、分布图

- 存在种子级或观测级分布时，使用小提琴图，并显示全部观测、中心均值/中位数和适用区间。
- 不得用仅显示汇总值的柱形图或均值点代替分布。
- SEAL 跨模型基准的每个展示指标必须显示 20 个划分种子的分布。
- 类别 precision、recall 和 F1 必须从与混淆矩阵相同的预测行重算每个种子的类别指标；显示全部 20 个点，并叠加小提琴和均值。
- 明确评价单位是划分种子、蛋白质、ORF，还是独立训练的模型。重复种子反映重采样变异，不代表独立生物学重复。

## 五、跨模型基准与 ESMC

- 评价五类蛋白质基准时不得遗漏 ESMC。
- ESMC-6B 是当前输入的 2,560 维扩展；必须使用相同的 1,418 个冻结标签、逐蛋白 L2 归一化、余弦距离、20 个分层划分、10-NN、平衡 K-means 抽样和 bootstrap。
- 不得暗示 ESMC 与 ProstT5、ProtT5 或 ProTrek 的 1,024 维坐标存在一一对应关系。
- 在图注和源数据说明中区分历史三模型基准与当前输入 ESMC 扩展。
- Source Data 必须保留输入哈希、accession 匹配、划分种子、预测、逐种子指标和 bootstrap 区间。

## 六、人类蛋白质组投影图

- 图若描述为 2w 人类蛋白质组投影，必须拟合并展示全部 20,420 个当前输入 Swiss-Prot 蛋白，而不是只显示 1,418 个带标签蛋白。
- 不属于五类基准标签的 19,002 个蛋白以浅灰背景显示；该密集层可在 SVG/PDF 中栅格化至 600 dpi 以控制文件大小。
- 1,418 个带标签蛋白必须作为可编辑矢量，使用全饱和类别颜色和不同点形叠加。
- 直接标注类别并显示计数；所有 t-SNE/UMAP 面板必须使用相同的类别和颜色。
- 灰色背景必须独立为栅格层；坐标轴、标签、图例和彩色观测保持可编辑矢量。
- 参数敏感性分析展示全部预设参数，不得只挑选视觉分离最好的结果。

## 七、主图 1–4 与 Figure 2 图谱/子图要求

- 保持 4 张作者确认的主图，不在只修改补充图的任务中静默重绘或替换主图。
- 主图 1 为已确认的概念与应用设计。若要求恢复早期稿件中的完整作者版本，使用 Word 中实际嵌入的完整图件和原始裁剪，不用近似重构图替代。
- 保持 Figure 2 已确认构图：中央 205,228 条目三维 t-SNE 图谱、8 个清晰分离的彩色区域、内侧家族子图和外侧代表结构。
- 主图谱同时提供 t-SNE 与 UMAP，以 t-SNE 为主；提供 2D/3D、有轴/无轴、多个视角和至少一个使 8 个清晰类别均接近可见外缘的 3D 视角。
- 显示全部点，不得因自动裁切丢掉极端观测。
- 未分配蛋白为浅灰；密集灰色层可栅格化，彩色注释和可编辑文字保持矢量。
- 同一家族出现在多个外围岛屿时，选择外围的代表区域标注，避免在整个图中重复标注同一家族；必要时把重复家族拆成单独的、清晰标识的子图组。作者确认设计使用多个 GPCR 相关区域时应保留。
- 8 个高亮家族必须是清晰、空间连贯的群体。不得把横跨多个不相关岛屿的宽泛标签或显著离群散点算作 8 个主要家族。
- 使用可复现的聚类/选择程序和明确标准，不得为了偏好视觉结果而调整标准化分析规则。
- 子图图例和颜色使用真实蛋白质家族/Pfam 注释，不得把局部 cluster ID 当作生物学标签。
- 家族子图内部，有注释蛋白使用该家族颜色或已记录的深色梯度，区域内没有保留注释的蛋白使用浅灰；不得给通用 cluster 颜色赋予生物学含义。
- 每个子图从自身蛋白质子集独立计算，x/y 数据轴视觉长度严格相等；打印尺寸下所有子图点必须清晰可辨。
- 每个选定家族输出距离家族中心最近的 10 个结构 FASTA 用于结构预测。项目已按每个家族 10 个预测结构进行过分析，重新预测前必须核对实际队列。

主图评价必须同时给出清晰分离的主家族图谱和独立家族级分析；protein kinase 等在空间上跨多个远隔亚家族的宽泛标签，不能替代视觉上连贯的家族区域。

## 八、结构重叠图

- 从一个参考结构出发，在明确共享核心上对齐 4–5 个代表结构。
- 项目可提供每家族 10 个预测结构；先分析全部结构，再选择共享核心对齐最有说服力的 4–5 个展示。
- 主要“all five, whole chains – front”视图显示全链 cartoon。
- 一个全饱和参考 cartoon 加若干仍可见的对齐半透明 cartoon。
- 可隐藏无关的柔性 loop、无序区和极低 pLDDT 片段，但必须记录；比较对象为核心结构区域。
- 只显示 cartoon，不显示原子。
- 必须确认显示的是目标蛋白 core、至少 4 个对齐核心可见，并沿用图谱中相同家族颜色。
- 不采用透明 surface 叠加，因为透明累积会造成重叠区域异常加深或含义不清。
- 参考 cartoon 和结构面板必须保留对应子图中的准确家族颜色；结构重叠图应与相应子图对应，不作为孤立装饰。

## 九、导出、栅格化与可编辑性

- 每张最终图提供 SVG、PDF 和 600-dpi PNG；所有要求的 JPG/HTML 文件也必须生成。
- 主图 Figure 2 还必须按适用性提供 t-SNE/UMAP、2D/3D、多个视角和有轴/无轴 JPG/SVG/HTML 版本。
- 每张补充图除 PDF/PNG 外，还必须具备 JPG、SVG 和 HTML 预览/链接。
- 在源图允许时，每个分析面板和面板字母必须有独立可编辑 SVG。
- 只允许密集未注释灰色背景层栅格化；点分布、高亮观测、坐标轴、标签、图例和统计标记保持矢量。
- 发布前清除旧 shared/panel SVG，确保 HTML 中每个链接均指向当前存在的面板。
- 检查全部页面图像加载，不得出现空面板、裁切或空心链接。
- 不得把栅格图放大后描述为恢复真实分辨率；必须写明源 dpi、裁剪和插值来源。

## 十、发布前强制审核

对 28 张补充图逐张检查：

- 最小文字 ≥8 pt；
- 轴标题/面板标题为 10 pt；
- 面板字母为 10 pt；
- 轴线和刻度为 0.4 pt，端点圆润；
- 常规数据框比例 0.9–1.1；
- 零文字碰撞、零文字越出画布/页面；
- 600-dpi PNG、可解析 SVG、单页可打开 PDF；
- 图号、面板字母、样本量/分母和源数据记录一致；
- 每个声明的面板都有当前独立 SVG；
- HTML 无过期、空洞或空面板链接；
- 在桌面和移动宽度实际检查浏览器渲染。

最终重生成后必须同时运行逐图、SVG/PDF 和 Source Data 审核。记录图片加载、面板覆盖、源哈希和未解决例外；不得仅凭视觉观察宣称最终合格。

## 十一、逐面板交付、标签排布与放行条件（1.1.0）

### 11.1 面板是交付单位

每个声明的面板都必须单独导出为可独立打开的可编辑 SVG，携带该面板自己的字母、轴标题、刻度标签、图形标记和注释。合成图应由这些面板装配而成，并可据此重现。合成图的裁剪、扁平化图像、或只存在于合成图中的面板，都不构成交付。

每张图应交付：合成 SVG、矢量 PDF、600-dpi PNG、600-dpi JPG、逐面板 SVG、共享图例或色标 SVG、图注、面板定义记录和审核记录。

### 11.2 自动检查只用于初筛

包围盒碰撞计数会漏掉真实缺陷：面板标题可能压在上一行的刻度标签上，类别标签可能落在点云内部，而文本—文本检测不会报警。报告碰撞数为零不能作为图件整洁的证据。每张图都必须按最终尺寸打开图像、逐面板检查，并记录检查结果。

### 11.3 标签排布

- 当锚点彼此接近时，类别、簇、区域和位点标签应放入边缘标签栈，并用引线连回锚点。
- 任何标签都不得覆盖数据点、坐标轴、刻度标签、面板标题、面板字母、色标或其他标签。
- 偏移量按各面板自身锚点几何计算；在不同锚点间套用同一个硬编码偏移属于缺陷。
- 当两个锚点间距小于标签高度时，将标签沿纵向展开，并绘制短线指向各自锚点。
- 图例已能无歧义识别的类别可以省略直接标签，前提是没有关键数值因此被隐藏。

### 11.4 行列表距预算

- 在每个数据框上方单独预留标题与面板字母带，在下方单独预留 x 刻度标签与轴标题带。
- 行间距必须大于上一行 x 刻度标签高度与下一行标题带之和。仅令坐标轴等宽并不能避免碰撞。
- 宽面板例外、色标和图例占用预留边距，不得压入数据区。
- 每条轴只使用一种数值记法，不得混用小数与科学计数法；共用指数文字不小于 8 pt。
- 出现碰撞时应增加画布高度，而不是缩小字号或删去轴标题。

### 11.5 28 张图的放行条件

只有在同一次重生成中满足以下条件才可放行：

- 全部 28 张合成图与每个面板 SVG 均由当前源数据重新生成；
- 每个面板 SVG 可打开、含活文字、且与合成图一致；
- 8 pt / 10 pt / 10 pt / 0.4 pt 与 0.9–1.1 常规数据框已在重生成文件上核验；
- 每张图的视觉检查均记录所发现并修复的缺陷；
- 无过期面板、图注或 HTML 链接；
- 正文引用、图注、计数与源数据记录与交付图件一致。
